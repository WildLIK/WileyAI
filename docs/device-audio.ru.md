# Звук Windows и проигрыватель — WileyAI 0.8.1

В разделе **Команды → Звук Windows** доступны системная громкость, mute и медиаклавиши. Те же действия выполняются из текстового чата и из распознанной голосовой реплики. Не требуется установка моделей или дополнительных Python-библиотек. Голосовой ввод использует выбранный распознаватель как обычно.

## Примеры

| Запрос | Действие |
| --- | --- |
| «Какая громкость?» | Прочитать уровень и состояние mute |
| «Громкость 35%», «установи громкость тридцать пять процентов» | Установить уровень от 0 до 100 |
| «Сделай громче», «можешь сделать тише?» | Прибавить/убавить 10 процентных пунктов |
| «Уменьши громкость на пять процентов» | Изменить уровень на указанное число пунктов |
| «Выключи звук», «верни звук» | Отключить/включить звук без смены уровня |
| «Следующий трек», «предыдущий трек» | Передать медиаклавишу Windows |
| «Переключи воспроизведение» | Передать клавишу воспроизведение/пауза |
| «Останови музыку» | Передать клавишу остановки |
| «Поставь музыку на паузу», «поставь на паузу» | Запросить паузу и проверить состояние плеера |
| «Продолжи музыку», «воспроизведи музыку» | Запросить воспроизведение и проверить состояние |
| «Где музыка?», «проверь проигрыватель» | Прочитать состояние без изменения |

Можно обращаться по имени, например «Уайли, сделай потише». Цитаты, отрицания, инструкции внутри документов и составные фразы с другими действиями не выполняются. Поддерживается ограниченный набор формулировок; свободный разбор задач и произвольные планы модели остаются отдельным этапом.

Меняется **устройство воспроизведения Windows по умолчанию для мультимедиа**. Оно может отличаться от динамика, выбранного для голоса Уайли. Установка громкости не снимает mute. Значение 0 не изменяет сам флаг mute. Относительные изменения ограничены диапазоном 0–100.

В 0.8.1 при наличии AIMP используется его Remote API: проверяется процесс-владелец окна управления, считывается состояние, команда отправляется с тайм-аутом, затем состояние проверяется ещё раз. AIMP имеет приоритет при одновременной работе нескольких плееров. Повторная пауза не возобновляет уже приостановленный плеер. Если AIMP отсутствует, используется текущая системная медиасессия Windows (SMTC). Не все проигрыватели публикуют такую сессию.

Ответ различает прочитанное состояние, подтверждённое изменение и отсутствие подтверждения. «Плеер сообщил воспроизведение» не проверяет слышимость звука, выбранный аудиовыход или наличие подходящего трека. Название трека пока не считывается. Если ответ плеера потерян после команды, второй переключатель автоматически не отправляется.

Для переключателя, остановки и треков при отсутствии доступного API остаются медиаклавиши Windows: результат зависит от активного плеера и явно помечается как неподтверждённый. Отдельные «пауза» и «продолжить» не заменяются слепым переключением. Остановка проигрывателя не заменяет остановку озвучки Уайли / Escape.

«Запустим музыку» и «включи музыку» сначала обращаются к доступному плееру. Если его нет, выбирается добавленное музыкальное приложение или запрашивается источник. Добавление плеера в команды само по себе не запускает трек.

## Доступ и интерфейс

**Команды → Доступ к инструментам → Управлять звуком и медиаклавишами Windows → Сохранить доступ**. Переключатель общий для окон, проверяется перед каждым действием и сохраняется после перезапуска. Доступ к открытиям и поиску управляется отдельно. Восстановление резервной копии сохраняет текущее разрешение на звук, в том числе при переносе подключений.

Ползунок меняет значение в форме; действие выполняется кнопкой **Применить громкость**. При открытии панели, возвращении фокуса и после действия считывается текущее состояние. **Обновить громкость** повторяет чтение. Несохранённое положение ползунка при обновлении не сбрасывается. Фоновый опрос и постоянный COM-объект не создаются.

Если устройство отсутствует/отключено, выводится ошибка, элементы громкости недоступны; после подключения нажмите «Обновить громкость». Медиаклавиши доступны независимо от считывания устройства. Изменения и ошибки попадают в журнал действий как `device.audio` с операцией и числом, без текста разговора.

В **Команды → Журнал действий Windows** видны результат инструмента, путь, состояние и PID, когда они прочитаны. Эти записи создаются ядром, а не текстом модели. Неопознанные короткие реплики о запуске не должны подтверждать выдуманное действие: типовые неподтверждённые заявления модели задерживаются до проверки и заменяются уточнением перед выводом и озвучкой. Это ограниченная защита от ошибочных утверждений, а не универсальное понимание искажённой речи.

Встроенные источники API: [AIMP SDK, apiRemote.h](https://aimp.ru/?do=download&os=windows&cat=sdk), [системные медиасессии Windows](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssessionmanager), [TryPauseAsync](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession.trypauseasync). Дополнительные Python-пакеты и платные сервисы для этого не нужны.

## Реализация и проверки

Типизированный `AudioAction` принимает только фиксированные операции и целые числа в допустимом диапазоне. API: `GET /device/audio`, `POST /device/audio`, `GET /device/media`; обычный `POST /commands` поддерживает предварительную проверку без действия. При чтении документа целиком и веб-поиске команды звука не выполняются. Результаты LLM никогда не передаются этому адаптеру как действия. Сценарии запуска по-прежнему содержат только открытия: произвольное смешивание шагов ещё не поддержано.

Используются [IAudioEndpointVolume](https://learn.microsoft.com/en-us/windows/win32/api/endpointvolume/nn-endpointvolume-iaudioendpointvolume) и [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput). Порядок COM-методов и GUID проверены по заголовкам Microsoft [endpointvolume.h](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/endpointvolume.h), [mmdeviceapi.h](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/mmdeviceapi.h). В каждом рабочем потоке COM инициализируется на время запроса, интерфейсы освобождаются при успехе и ошибках. Одновременные изменения внутри WileyAI сериализуются.

Проверены русские формулировки, диапазоны и строгие аргументы, отсутствие вызова LLM, журнал, предварительная проверка, запрет доступа и сохранение при восстановлении, параллельные изменения, освобождение COM при ошибках, ABI x64 и парность нажатия/отпускания медиаклавиш. Electron-проверка охватывает ползунок, кнопки, изменение разрешений, черновик и узкое окно. Настоящее чтение громкости проверено на Windows; тестовые изменения и медиаклавиши используют подставные адаптеры и не меняют звук пользователя.
