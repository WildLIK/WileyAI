# Полный пересказ большого файла

Большой файл хранится в библиотеке целиком, но обычный вопрос получает только выбранные отрывки в пределах контекста модели. Например, книга на 639 тысяч символов не помещается одновременно в контекст на 4096 токенов. Конец отрывка не является концом файла. Под обычным ответом теперь видно количество использованных символов относительно полного извлечённого текста; модель также получает это различие явно.

## Запуск

Прикрепите файл к чату и нажмите **«Пересказать целиком»** рядом с его плашкой. Если поле сообщения заполнено, текст используется как пожелание к итоговому пересказу. Пустое поле запускает пересказ с порядком событий и объяснением финала.

Можно общаться обычными фразами, например **«Мне нужен краткий пересказ от начала до конца»** или **«Можешь рассказать всю историю, включая финал?»**. Выбранная модель получает описание доступного действия и сама решает по смыслу просьбы и контексту, нужно ли прочитать все части. Обязательного списка команд и проверки ключевых слов больше нет. Для точечных вопросов модель может сразу ответить по отрывкам. Кнопка запускает полное чтение напрямую, минуя решение модели.

Если большой файл виден лишь частично, сначала выполняется короткий скрытый выбор способа чтения той же моделью: весь документ или выбранные отрывки. Это отдельный запрос с лимитом 64 токена и температурой 0, а не поиск команды в обычном ответе. В Ollama используется [JSON Schema через поле format](https://docs.ollama.com/capabilities/structured-outputs), в совместимом API — response_format. При явном отказе совместимого сервиса от этого формата допускается одна попытка без него; ключи, квоты, ошибки сервера и оборванные запросы автоматически не повторяются. Полученное решение проверяется независимо от формата сервиса. Пояснения вокруг JSON остаются внутри этого этапа и не показываются пользователю.

После выбора полного чтения запускается прогресс и собираются конспекты; после выбора отрывков сразу начинается обычный поток ответа. Небольшой файл, уже целиком переданный модели, обходится без дополнительного выбора, как и прямой запуск кнопкой. Для большого файла этап выбора добавляет небольшую задержку и один короткий запрос к выбранному провайдеру. Объём контекста не увеличивается. Служебных команд в инструкции к обычному ответу больше нет.

## Как проходит чтение

1. Весь извлечённый текст выбранных файлов делится на последовательные части без пропусков. По возможности граница проходит у конца абзаца или предложения.
2. Выбранная модель по очереди составляет короткие конспекты частей. Контекст модели не увеличивается; промежуточные ответы имеют небольшой отдельный лимит.
3. Если конспекты не помещаются в итоговый контекст, соседние группы последовательно сжимаются. Порядок файлов и частей сохраняется.
4. По итоговым конспектам модель пишет связный пересказ. В сообщении указываются имена обработанных файлов и количество частей.

Промежуточные конспекты не озвучиваются и не добавляются в память владельца. В процессе видны название файла, номер части, анимированная полоса и счётчик завершённых частей. Во время первого запроса показывается движущийся индикатор ожидания; после первой части — процент текущего этапа. При сборке конспектов начинается отдельный этап, затем появляется «Пишу пересказ». Это не оценка оставшегося времени.

Кнопка **«Остановить»** у полосы, остановка ответа в поле сообщения и глобальная остановка отменяют текущий запрос и следующие части. Ошибка или отмена во время промежуточного чтения не сохраняет готовый пересказ и не заявляет о полном прочтении.

## Время, ресурсы и ограничения

Большая книга может потребовать десятков или сотен последовательных запросов. Время зависит от модели, контекста, скорости ПК или облачного сервиса. Облачная модель использует свой тариф для каждого запроса. Увеличение контекста может сократить число частей, но требует больше ресурсов; приложение автоматически его не повышает и не переключает провайдера.

Это сжатый пересказ всего извлечённого текста. При многоступенчатом сжатии могут теряться второстепенные детали; точность пересказа зависит от выбранной модели. Для подробного разбора главы или проверки цитаты нужен отдельный запрос к исходному тексту. OCR изображений и сканов этот режим не добавляет.

Промежуточные конспекты существуют в оперативной памяти на время запроса. Возобновление с места остановки и постоянный кеш пока не реализованы: повторный запуск читает файл заново. Итоговый ответ сохраняется с историей и резервной копией. Он не выдаётся за набор дословных отрывков в блоке «Документы в контексте». Формат копии остаётся 7. Следующие обычные вопросы используют свой отбор фрагментов и ограниченную историю; весь текст книги не становится постоянным контекстом модели.

## Проверки

`tests/test_document_summary.py` проверяет полное покрытие длинного текста и финала, границы частей, размер промежуточных запросов, сборку конспектов, ошибки и пустые ответы, отмену, изоляцию проектов и отсутствие исполнения команд или записи памяти в режиме пересказа. Дополнительно проверяются решение после свободной фразы и уточнения, строгая проверка режима, пояснения вокруг служебного JSON, отмена самого этапа выбора, пропуск выбора для целиком видимого файла и сохранение обычного потока ответа при ошибке. `tests/test_providers.py` проверяет поля схемы обоих протоколов, небольшой лимит и единственный допустимый повтор при неподдерживаемом формате.

`tests/desktop/document-summary.spec.ts` использует настоящий Electron, временную библиотеку и контролируемый HTTP-сервис модели. Проверяются частичный контекст обычного ответа, кнопка полного пересказа, анимация до первой завершённой части, продвижение счётчика, остановка сетевого запроса, полное чтение после обычного **«прочитай»**, передача всех частей до последней строки и сохранение итогового ответа после перезапуска. Тестовый сервис намеренно добавляет пояснение перед служебным JSON: оно не попадает в чат.

`tests/test_live_document_reading.py` — дополнительная проверка с настоящей Qwen3.5:4b и временной библиотекой. По фразе **«прочитай»** модель выбирает чтение всего тестового файла; проверяется отправка всех частей без пропусков и сохранение пересказа без служебного JSON. Запуск: `WILEYAI_LIVE_TESTS=1`, при необходимости `WILEYAI_LIVE_DOCUMENT_URL` задаёт адрес локального тестового сервера. Проверка не скачивает модели и не использует пользовательскую книгу. На текущем ПК полный прогон с отдельным временным сервером занял около 11 секунд, две части; это замер конкретной короткой проверки, а не оценка времени обработки большой книги.
