# Реальная поддержка нейросетей в Gateway

Срез 29.10.2026. **Ни один личный веб-аккаунт в этом этапе не использовался.**
Все остальные сообщения о проверках относятся к собственному протоколу и
изолированным mock-провайдерам, а не к доступности стороннего бесплатного сервиса.
[Исследование 24 проектов](research/gateway-comparison.ru.md),
[архитектура](gateway-architecture.ru.md), [развёртывание](gateway-deploy.ru.md).

Обозначения: **К** — реализовано и проверено автоматически на mock-протоколе;
**У** — условно, только при явной метаинформации фактической модели;
**Нет** — не реализовано/не разрешается этим адаптером. Возможности официального
сайта не считаются возможностями Gateway. Не закреплён ни один production model ID.

## Что осталось за пределами этой реализации

- Реальная приёмка ChatGPT аккаунтом и на VPS; затем проверка разрешённых функций
  фактических моделей, квоты, истечения сессии и региональных ошибок.
- Разрешённые адаптеры остальных сервисов. Приоритет DeepSeek→Qwen→GLM выполнен
  как исследование; без допустимого интерфейса их внедрение не объявлено успешным.
- Полный Android UI ветвления/редактирования/повтора,
  media artifacts, rich Markdown с подсветкой кода. Сейчас текст/SSE,
  копирование и источники используют существующий renderer.
- Native/emulated tools, MCP и облачные голосовые модули. Текст модели не может
  выполнить команду Android; прежняя локальная система разрешений сохранена.
- Устанавливаемые подписанные расширения: есть контракт четырёх типов адаптеров,
  но пока только доверенные серверные модули в allowlist. Загрузка удалённого кода
  не включена. OAuth методов нет у неподдержанных сервисов.
- Распределённые job/tenant provisioning, отдельный admin UI, шифрование с KMS,
  ротация master key, автоматический retention/cleanup и нагрузочное тестирование.
  Это self-hosted preview одного процесса с изоляцией owner, не SaaS-ready система.

Запросы ошибок не повторяются бесконечно; повтор чтения SSE ограничен тремя
соединениями. Лимиты файлов, диалогов и длины ответа заданы явно. При удалении
вложения, использованного старым сообщением, продолжение такого контекста может
дать not_found: нужен UI управления вложениями/retention со ссылочной целостностью.
Прежний local/direct API путь доступен при недоступности Gateway, но выбор делает
пользователь. Автоматического fallback с передачей данных нет.
