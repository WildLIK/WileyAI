# WileyAI Gateway: свой VPS и Android

Состояние 29.10.2026: **preview**, а не готовая замена всех веб-чатов.
Рабочий сетевой протокол проверен с изолированным тестовым провайдером и Java
транспортом Android. ChatGPT OAuth/Responses проверены на подписанных mock-ответах.
Реальный вход аккаунтом, публичный VPS/HTTPS и Docker в этой среде не проверены:
нет предоставленного VPS/аккаунта и установленного Docker. Это отдельные пункты
приёмки, а не подразумеваемый успех сборки.

## Что требуется

Linux VPS с Docker Engine и Compose, домен с A/AAAA на сервер, входящие TCP 80/443,
исходящий HTTPS к разрешённым провайдерам. Домашний ПК не нужен. Порт 48500 наружу
не публикуется; существующий настольный шлюз 48443 к этому серверу не относится.
Контейнер Gateway запускается без root, с read-only кодом, отдельной базой и ключом.
Ограничения 768 МиБ/1 CPU — защитные настройки Compose, **не измеренная потребность**
и не обещание определённого числа пользователей. Браузер серверу не нужен.

Получите проверенную вами версию репозитория. Следующие команды выполняются из
его корня на **вашем Linux VPS**. Для каталогов/портов нужны административные права.
Проверьте, что подсеть `172.30.84.0/24` свободна; при изменении согласуйте адрес
Caddy в Compose и `--forwarded-allow-ips`. Не ставьте `*` в доверенные proxy IP.

```sh
docker build -f deploy/gateway/Dockerfile -t wileyai-gateway:preview .
sudo install -d -m 700 -o 10001 -g 10001 /srv/wileyai/data /srv/wileyai/secrets
docker run --rm --user 10001:10001 \
  -v /srv/wileyai/data:/data -v /srv/wileyai/secrets:/bootstrap \
  wileyai-gateway:preview init --data-dir /data --key-file /bootstrap/master.key
export GATEWAY_DOMAIN=ai.your-domain.example
docker compose -f deploy/gateway/compose.yaml up -d
curl --fail "https://$GATEWAY_DOMAIN/healthz"
```

Замените пример домена своим. Сохраните `GATEWAY_DOMAIN` в приватном окружении
оператора либо в игнорируемом `.env` рядом с Compose. Инициализацию выполняют
**один раз**: она отказывается перезаписывать базу/ключ. `restart: unless-stopped`
восстанавливает сервис после перезагрузки, если Docker запускается автоматически.

В `/srv/wileyai/data/owner.token` находится административный токен. Через SSH
выпустите отдельный клиентский токен (не вставляйте его в URL, Git или скриншоты):

```sh
sudo env GATEWAY_DOMAIN="$GATEWAY_DOMAIN" python3 - <<'PY'
import json, os, pathlib, urllib.request
token = pathlib.Path('/srv/wileyai/data/owner.token').read_text().strip()
request = urllib.request.Request('https://' + os.environ['GATEWAY_DOMAIN'] + '/api/v1/clients',
    data=json.dumps({'label':'Android'}).encode(), method='POST',
    headers={'Authorization':'Bearer ' + token, 'Content-Type':'application/json'})
with urllib.request.urlopen(request, timeout=15) as response:
    issued = json.load(response)['token']
path = pathlib.Path('/srv/wileyai/data/android.token')
path.touch(mode=0o600, exist_ok=False)
path.write_text(issued + '\n')
print('Клиентский токен сохранён в', path)
PY
```

Прочитайте `android.token` через свою SSH-сессию и введите на телефоне в
**Настройки → Нейросети → Подключения → Удалённые серверы**, вместе с
`https://ваш-домен`. На Android профиль и токен шифруются ключом Android Keystore.
Клиентский токен даёт доступ ко всем данным своего владельца: не делитесь им.
Административный токен оставьте на VPS. Это собственные токены Gateway, а не
платные ключи нейросетей.

## Подключение аккаунта

1. Откройте «Веб-аккаунты», затем поддержанный экспериментальный вход ChatGPT.
2. Прочитайте согласие на передачу сообщений своему Gateway и выбранному сервису.
3. Вход откроется **в системном браузере** на `auth.openai.com`. Пароль вводится
   только там. Приложение принимает одноразовый callback на loopback телефона,
   проверяет state и передаёт код аутентифицированному собственному серверу.
4. После входа выберите аккаунт → «Выбрать модель». Каталог загружается заново
   из разрешений аккаунта. Пустой каталог не заменяется фиктивными моделями.
5. Нажмите «Использовать» и вернитесь в чат. В заголовке будет выбранный источник.

Поддержанный OpenAI SIWC — доступ к разрешённым функциям плана, **не копия
chatgpt.com**: история сайта, генерация изображений, аудио/видео и hosted MCP
не переносятся. Подробности и границы допуска:
[официальный SIWC](https://developers.openai.com/siwc/token-sharing-open-source),
[собственный VM](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms),
[preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).
Наш Android → Gateway handoff требует реальной проверки регистрации/аккаунта.
Если OpenAI не допускает конкретное размещение или план, вход остаётся недоступным;
чужой client ID, cookies и обходы не используются. Hosted-коммерческий сервис
может требовать отдельного допуска.

DeepSeek, Qwen, GLM и остальные видны с точной причиной недоступности. Отсутствие
поддержанного входа не лечится установкой случайного Web-to-API proxy. Смена VPS
не гарантирует обход региональных ограничений. [Матрица возможностей](gateway-support.ru.md).

## Сообщения, вложения и обрывы

Голос распознаётся/озвучивается Android; команды телефону остаются локальными.
Gateway используется для свободного разговора при явном выборе модели. Локальная
Qwen и прямой официальный API сохраняются как отдельные варианты. Автоматической
передачи другому провайдеру нет.

Для новой серверной беседы передаются до 8 последних текстовых сообщений телефона;
далее сервер хранит собственный контекст и отправляет последние 32 сообщения.
Это не синхронизация всех исторических чатов сайта. Черновики телефона сохраняются
существующей подсистемой. Текст SSE отображается постепенно; источники дописываются
ссылками. Доступны копирование и существующее выделение текста.

«Прикрепить файл» активно только при заявленной capabilities поддержке. До 5 файлов
по 10 МиБ; фото, PDF/DOCX/TXT/CSV/JSON проходят MIME/размер/принадлежность и базовые
проверки сигнатур. Это не полноценный антивирус. Сам файл сначала попадает на ваш
Gateway, к нейросети — после «Отправить». Файлы не исполняются и не задают путь сервера.

При обрыве чата откройте «Подключения → Оборвавшийся ответ → Восстановить»:
читается прежний job. Незавершённый запрос блокирует новую отправку до восстановления
или подтверждённой отмены. Даже если ACK потерян, сохранённый request_id защищает
от повторной генерации. Восстановленный текст добавляется в существующий чат
телефона с защитой от дубля; удалённый пользователем чат не воссоздаётся.
После перезапуска самого Gateway генерация не возобновляется скрыто: сохраняется
частичный результат с состоянием interrupted.

Сервер поддерживает fork до выбранного сообщения для редактирования/повтора;
полный интерфейс ветвления/повторной генерации Android — следующий этап.
История Gateway доступна в «Подключения → Диалоги на сервере» (просмотр последних
30 сообщений и удаление с подтверждением), читается через
`GET /api/v1/conversations/{id}?limit=50&before=N` (индекс N, максимум 200 за страницу)
и удаляется
`DELETE` того же маршрута. Удаление чата только с телефона пока не удаляет его
серверную копию. `DELETE /api/v1/connections/{id}` удаляет авторизацию отдельно.

## Необязательные официальные API

Владелец может добавить JSON `[{"id":"official-example","name":"Мой API",
"endpoint":"https://api.example.org/v1"}]` вне Git и передать `serve --profiles`.
В Compose файл надо дополнительно смонтировать `:ro` и добавить аргумент.
URL задаёт администратор, сообщения и Android его не меняют. После этого в категории
«Официальные API» появляется источник; пользователь вводит свой API credential
по желанию. Только динамический `/models`, текст и streaming; остальные возможности
не выводятся из названия модели. Прямой Android Chat Completions также сохранён.

## Обслуживание и удаление

Используется **один** процесс Gateway и SQLite. Не запускайте несколько workers
с этой базой: leases/job cancellation ещё не распределённые. База/ключ требуют
резервного копирования: остановите Gateway, сохраните весь `/srv/wileyai/data`
и отдельно защищённый master.key, затем запустите. Потеря ключа необратима;
получение и базы, и ключа раскрывает сессии. AES-GCM не защищает от захвата root VPS.
После отсоединения аккаунта проверьте подтверждение отзыва у провайдера.

Обновление: проверить изменения/зависимости, сделать backup, пересобрать образ,
запустить Compose с `--build`. Базовые образы в примере закреплены по семейству,
не по digest; для production оператор должен зафиксировать проверенные digests
и транзитивный lock/SBOM, выполнить vulnerability scan и TLS/login приёмку.
Известных CVE здесь не объявляется «нет»: сканирование образа не выполнялось.
Access log отключён; не включайте HTTP debug или request-body logging.

Удалить данные: отключить аккаунт с отзывом, удалить нужные серверные диалоги и
вложения их DELETE-маршрутами. Отозвать текущий токен: `DELETE /api/v1/client-session`.
Полное удаление сервера/секретов выполняет владелец после backup и проверки путей.

## Проверки перед реальным использованием

Автоматически проверены владение данными, AEAD, state/nonce/PKCE/JWT, refresh/revoke,
модели, ошибки квот, partial failure, отмена, request idempotency, SSE replay и
реальный loopback HTTP/SSE Java↔Python. Отдельно остаются: реальный разрешённый вход
аккаунта, запрос/ответ, истечение сессии, HTTPS VPS, перезагрузка, backup/restore,
мобильная сеть и установка APK на S23+. Не экспортируйте личные cookies для тестов.
