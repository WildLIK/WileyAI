# ChatGPT через вход в аккаунт

В **Настройки → Мозг → Движок** выберите **ChatGPT · вход через аккаунт** и
нажмите **Continue with ChatGPT**. Откроется системный браузер. Войдите в нужный
аккаунт, выберите рабочее пространство, если оно предлагается, и разрешите
WileyAI использовать доступный план ChatGPT. API-ключ и пароль в WileyAI вводить
не нужно. После успешного входа доступная модель выбирается из каталога аккаунта,
подключение сохраняется. Другую модель можно выбрать в списке и сохранить настройки.

Запросы WileyAI используют общие лимиты вашего плана; отдельный дополнительный
лимит от подключения не появляется. Доступность зависит от аккаунта, разрешений
и выбранной модели. Кнопка **«Управлять лимитами ChatGPT»** открывает настройки
использования ChatGPT. При исчерпании лимита запрос останавливается без перехода
на оплату по API или на другого провайдера.

В голосовом разговоре сохраняется цепочка WileyAI: распознавание вашей речи,
ответ модели ChatGPT, выбранная местная или облачная озвучка, движения феи.
Переписка, память и инструменты WileyAI работают в своём локальном контексте.
История веб-чатов ChatGPT не запрашивается.

Сессия автоматически обновляется, пока разрешение действует. **«Другой аккаунт»**
начинает новый вход; действующее подключение заменяется только после проверки
новой личности. **«Отменить вход»** закрывает незавершённую попытку. В настройках
доступна кнопка **«Отключить ChatGPT»**. Если отзыв на сервере не подтверждён из-за
сети, приложение сообщает об этом и очищает локальные токены. Дополнительно
доступ можно отозвать в настройках подключений ChatGPT.

## Если разрешение в ChatGPT есть, а подключение не появилось

Регистрация приложения и получение сессии в WileyAI — отдельные шаги. Если после
подтверждения в браузере возникает сетевая ошибка, запись WileyAI может уже
появиться в лимитах ChatGPT, а локальный вход ещё не завершиться.

При ошибке установления соединения WileyAI делает до трёх попыток с короткой
паузой. Чтение публичных данных проверки также можно повторить. Если соединение
оборвалось после отправки кода входа или обновления сессии, запрос не повторяется
автоматически: такой код или вращаемый refresh token уже мог быть использован.
Вместо создания новой регистрации сохраняется выданный идентификатор незавершённого
входа; он не даёт доступа к моделям до проверки личности и разрешений.

Сетевые запросы входа и ответа учитывают системный/настроенный через окружение
прокси. Если VPN работает только расширением браузера, он может не охватывать
ядро WileyAI. Нужна доступность серверов OpenAI из самого приложения. Проверка
сертификатов HTTPS остаётся включённой.

Вернитесь в **Настройки → Мозг** и нажмите **Проверить подключение**. Конкретная
ошибка и этап теперь отображаются и на странице возврата в браузере, и в WileyAI.
Сетевая диагностика различает соединение, DNS, сертификаты, прокси и таймаут.
Последний результат сохраняется в `logs/chatgpt-login.json` каталога данных;
токены, код входа, адрес callback, PKCE и пароль туда не записываются. Следующая
попытка или успешный вход очищают старую ошибку. После обновления кода/сборки
перезапустите приложение и начните вход заново.

## Как устроено подключение

Используется официальный Sign in with ChatGPT для локальных приложений:
динамическая регистрация клиента, OAuth Authorization Code с PKCE S256, одноразовый
loopback callback на `127.0.0.1`, случайные state и OIDC nonce. Подпись ID token,
issuer, audience, срок действия и личность проверяются через опубликованный JWKS.
Повторный вход использует выданный client ID, стабильный непрозрачный ID установки
и новый PKCE. Пароль остаётся на стороне OpenAI.

Токены хранятся в системном хранилище учётных данных отдельными атомарно
обновляемыми поколениями, с учётом ограничения размера Windows Credential Manager.
Они не попадают в Settings, SQLite, браузерное хранилище, резервные копии и логи.
Windows ограничивает одну запись `CredentialBlob` 2560 байтами. Библиотека
хранилища использует UTF-16, поэтому JSON сессии разбивается на ASCII-части по
1000 символов (до 2000 байт), с атомарным переключением указателя после записи
всех частей. Чтение прежнего формата сохраняется. Исправлена ошибка, при которой
части по 1800 символов превышали лимит Windows и вход завершался отказом
сохранения. Проверка с настоящим Windows Credential Manager использует только
синтетическую сессию в отдельном временном пространстве имён:

```powershell
$env:WILEYAI_CREDENTIAL_TEST='1'
node scripts/python.mjs -m pytest tests/test_chatgpt.py -k real_windows -q -s
```

SQLite-файл `chatgpt-session.lock` содержит только межпроцессную блокировку
обновления сессии. Импорт копии не выбирает регистрацию из другого профиля.

Модели загружаются из каталога авторизованного аккаунта. Текст передаётся в
публичный Responses API с `store: false` и `stream: true`; системные инструкции
WileyAI передаются как developer messages, необходимая история — в каждом запросе.
Поток считается завершённым только по `response.completed`. Ошибки лимитов,
незавершённый поток и отказ в разрешении обрабатываются отдельно. Поддерживается
существующая защита WileyAI от повторяющейся генерации и остановка ответа.

- [Модели и запросы](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).
- [Сессии и обновление токенов](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).
- [Ограничения режима](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Автоматические проверки используют локальный OAuth callback, тестовые подписанные
ID tokens и фикстуры HTTP/SSE. Они не входят в личный аккаунт и не расходуют его
лимиты. Реальный доступ к моделям подтверждается после входа владельца аккаунта.
