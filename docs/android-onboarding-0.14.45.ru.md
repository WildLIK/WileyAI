# WileyAI Android 0.14.45. Настройка первого запуска

Проверено 27 ноября 2026 года. Кандидат имеет versionCode 87 и прежний идентификатор `ru.wildlik.wileyai.mobile`. Текущий опубликованный выпуск GitHub остаётся 0.14.44.

## Ошибка 0.14.44 и исправление

Проверены подпись манифеста и SHA‑256 APK, скачанного с GitHub Releases. В APK есть Silero VAD и нативные библиотеки Vosk, sherpa‑onnx и llama.cpp. `wake-stage1/campplus.onnx`, `wake-stage1/C_v2.onnx` и экспериментальные JNI-библиотеки LiveKit отсутствуют. Release собирался из чистой копии Git, а задача, копирующая исследовательские модели из `local/`, подключена к debug. Экран регистрации открывался независимо от состава APK и пытался прочитать CAM++ только при нажатии «Сохранить».

На эмуляторе установлена именно опубликованная 0.14.44. После трёх записей с виртуального аудиовхода нажатие «Сохранить профиль владельца» показало `Ошибка регистрации: wake-stage1/campplus.onnx`. Качество этих записей не оценивалось. [Публичный выпуск 0.14.44](https://github.com/WildLIK/WileyAI/releases/tag/v0.14.44).

В 0.14.45 `scripts/prepare-android-camplus.py` воспроизводимо получает 28 281 165 байт из sherpa‑onnx, проверяет SHA‑256 `53cab20ba8f2eb2f6e2d89ecc18e88ef3222169b61b4419cbc13666744a4574b` и атомарно публикует проверенный файл в локальных входах сборки. Gradle включает его в Android APK. Публичная сборка требует также sherpa‑onnx. При входе в «Мой голос» проверяются SHA‑256, извлечение и запуск CAM++. Повреждённая распакованная копия восстанавливается из APK. При проблеме запись блокируется до успешной проверки. Голосовые фразы обрабатываются в памяти, профиль хранится локально. Аудит APK допускает ровно закреплённые веса CAM++ и Silero. Карточка модели ModelScope, ревизия `v1.0.0`, указывает Apache License 2.0. [Карточка модели](https://modelscope.cn/models/iic/speech_campplus_sv_zh_en_16k-common_advanced) · [исходный экспорт sherpa‑onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models).

Выпускать файл можно после документированного разрешения по частным записям и медиа и проверки применимости условий Golos. В 0.14.45 для фонового вызова доступен Vosk. Профиль CAM++ можно создать и проверять отдельно. Для фильтра голосового вызова нужен совместимый детектор и действующий профиль. Прежний выбор движка сохраняется в настройках.

## Путь пользователя

1. Первый обычный запуск открывает приветствие с логотипом WL. При системной теме мастер использует существующую тёмную «Аврору», а выбранная вручную тема сохраняется. Шаг сохраняется при перезапуске. В «Настройках» есть ссылка для повторного открытия мастера.
2. Микрофон, уведомления и Bluetooth запрашиваются отдельно, после объяснения. Первый запрос и допустимый повтор использует системное окно. Для заблокированного запроса и специальных доступов есть переход в настройки Android. Изменения видны сразу после ответа или возврата.
3. Три раскрывающихся раздела ведут к существующим менеджерам Vosk, GigaAM, озвучки и Qwen. Доступны ручное подтверждение загрузки, прогресс и пауза. Импорт Qwen по-прежнему принимает совместимый GGUF с проверкой контрольной суммы из каталога. Системное распознавание и GigaAM в ручном режиме не требуют наличия Vosk. Для фонового вызова через Vosk нужен его комплект.
4. Настройка вызова включает выбор цифрового помощника, запуск и остановку фонового микрофона, выбор доступного движка и необязательную регистрацию голоса. Диалоги недостающих речевых компонентов и разговорной модели ведут сразу к нужным настройкам.
5. Итоговый экран показывает установку и доступность компонентов. Проверка голосовой команды предназначена для локального вопроса о времени. Озвучка отвечает при наличии русского офлайн-голоса. Свободный разговор требует модели, а системные команды работают без неё.

На физическом телефоне новую версию не проверяли. Живая фраза вызова, распознавание команды реальным микрофоном, ответ через системный русский TTS и работа с физической Bluetooth-гарнитурой остаются для аппаратной проверки. В чистом сценарии установили Vosk и пропустили GigaAM и Qwen.

Эти проверки выполнены на предварительной сборке. Подписанные файлы для публикации собираются из зафиксированного дерева. Проверка установщика Windows опирается на подписанный манифест и SHA-256.
