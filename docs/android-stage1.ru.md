# Android: аудит и безопасная миграция, этап 1

Дата: 28 октября 2026. Исходный клиент: 0.2.0, Java, Android API 26–34,
без сторонних Android-зависимостей. Windows остаётся на своей версии.

## Что найдено до изменений

- Работают сопряжение по одноразовому коду, Keystore/AES-GCM, HTTPS с pin
  сертификата, частные IPv4/Tailscale, переключение адресов, потоковый чат,
  задачи/заметки, запись микрофона и воспроизведение ответа.
- Чаты, распознавание, синтез, модели, память и задачи находятся на Windows.
  Без профиля подключения Activity открывает только сопряжение.
- `PhoneCommands` уже разбирает ограниченные команды без LLM. Запуск приложений,
  сайтов, медиаклавиши и громкость исполняются Android API внутри Activity.
- `MainActivity` совмещает UI, сеть, ключи, историю, команды и голос.
  Локального хранилища истории и настроек оформления нет.
- Палитры находятся в `src/themes.css`, имена в `src/appearance.ts`.
  Фея использует Three.js/VRM: перенос движка в первый этап не входит.
- Python-провайдеры, Ollama/GGUF и речевые движки используют серверные зависимости
  и Windows keyring; их нельзя считать готовыми движками Android или копировать
  вместе с токенами. Переиспользуем протокол ПК и семантику, а не runtime.
- CI собирал только Windows. Имеются pytest шлюза и JVM-пробы pin/команд.

## Границы первого этапа

1. Выделить `PcGateway`, `SettingsRepository`, `PhoneActionEngine` из Activity.
2. Добавить отдельную версионированную SQLite-базу телефонных чатов: сообщения,
   заголовки, черновики. Записи выполнять последовательно вне UI-потока.
3. Открывать телефонный чат без сети/ПК. Команды телефона исполнять без модели;
   отсутствие разговорной модели объяснять явно, не имитируя ответ LLM.
4. Навигация: чат, модели, возможности, настройки. Статичные градиенты и токены
   четырёх настоящих тем, системный выбор светлой/тёмной. Нет тяжёлого фона,
   постоянных декоративных анимаций и дополнительных разрешений.
5. Базовый каталог различает встроенные функции, функции ПК и будущие движки.
   Не добавлять фиктивные загрузки, непроверенные URL весов и обещания совместимости.
6. Сохранить существующий компьютерный чат, задачи/заметки, голос, TLS и подпись APK.

## Совместимость и данные

- Имя пакета и ключ debug-подписи сохраняются, versionCode увеличивается.
- Старый preference `wiley-mobile/connection` и alias Keystore
  `wileyai.mobile.connection.v1` читаются в прежнем формате. Read-aloud сохраняется.
- История Windows не переносится, не удаляется и не синхронизируется автоматически.
  У телефона и ПК отдельные пространства ID. Выбор режима явный; автоматической
  передачи телефонных сообщений в сеть нет. Повтор/редактирование — новый запрос.
- SQLite v1 создаётся отдельно; будущие обновления требуют явной миграции,
  неизвестная версия вызывает ошибку вместо удаления базы. Удаление чата с
  сообщениями транзакционно и требует подтверждения.
- После сбоя отправки телефонная история остаётся; сбой записи не считается успехом.
  Фоновые сетевые ответы не должны перерисовывать другой экран/чат.
- Утрата Keystore не маскируется удалением профиля: предлагается повторное сопряжение.

## Решение об интерфейсе

Первый этап сохраняет Java/Views, обновляя существующий экран, а не создавая
второе приложение. Kotlin/Compose/Material 3 ещё не подключены и не проверены
в текущей сборке. Следующий UI-этап — отдельный ComposeView со своим состоянием,
затем постепенная замена экранов после UI-проверок. Это соответствует
[рекомендации Android о постепенном переходе](https://developer.android.com/develop/ui/compose/migrate/strategy).
SQLiteOpenHelper поддерживает версию схемы и транзакционные миграции:
[Android API](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper).
