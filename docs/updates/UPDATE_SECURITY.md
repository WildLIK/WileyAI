# Модель доверия

- Доверенный публичный ключ P‑256 SPKI запекается в сборку. Закрытый ключ хранится у подписанта. Сборка без ключа не устанавливает выпуски через встроенный канал.
- В JSON-обёртке поля `payload` и `signature` кодируются Base64. Подписываются точные UTF‑8 байты вложенного JSON. Windows использует ECDSA P‑256/SHA‑256, Android проверяет подпись через Java Security. Формат DER устраняет необходимость сериализовать JSON заново при проверке.
- Подпись манифеста v2 связывает тег, дату и заметки, имена, версии, размеры и SHA‑256 обоих артефактов. В Android в подписанные данные входят package ID, versionCode и SHA‑256 сертификата APK. Заменить хеш на странице GitHub недостаточно, чтобы пройти эту проверку.
- URL строятся локально из имени разрешённого артефакта и тега. Запрос списка допускается только к `api.github.com`. Для активов используются `github.com`, `release-assets.githubusercontent.com` и `objects.githubusercontent.com`, с ограничением переадресаций. HTTP, иной порт или учётные данные в URL отклоняются.
- Загрузка ограничена подписанным размером и проверкой свободного места. Перед установкой на Windows выполняется повторный хеш, на Android проверяются пакет и сертификат. Режим `--allow-unsigned-windows` допускает только статус Authenticode `NotSigned`. Недействительная подпись или неверная встроенная версия останавливают подготовку. Клиент проверяет установщик по подписанному SHA‑256. Этот механизм не заменяет OS-подпись первого установщика.
- Защита от понижения сравнивает с установленной версией. Пока APK ещё не установлен, публикация списка GitHub теоретически может скрыть новый выпуск или показать иной ранее подписанный выпуск, который тоже новее установленного. Клиенты не используют сервер времени, историю отзыва ключей или TUF. Необходимо ограничивать репозиторные права и отзывать при необходимости сам GitHub Release.

Хранить ключ обновлений отдельно от Windows Authenticode и Android keystore. Ротация APK-сертификата и SPKI требует заранее выпускаемого переходного клиента. Схема требует точного совпадения текущего Android-сертификата. Автоматической ротации по signing lineage нет. [Подписи Android](https://developer.android.com/studio/publish/app-signing).
