# Подготовка и выпуск

Публичный API `WildLIK/WileyAI` 26 ноября 2026 года ответил HTTP 200. Последний стабильный выпуск `v0.14.0` содержит `WileyAI-Setup-0.14.0-x64.exe` и `SHA256SUMS.txt`. APK и подписанного манифеста в нём нет. [Релизы](https://github.com/WildLIK/WileyAI/releases).

## Воспроизводимая сборка

1. Повысьте общую версию и Android versionCode в `release-version.json`. Синхронизируйте версии в `package.json`, `package-lock.json`, `pyproject.toml` и `uv.lock`. Gradle и Python читают общую версию из JSON. Для этой сборки используются `0.14.44` и versionCode 86. Один тег `vMAJOR.MINOR.PATCH` должен содержать оба артефакта.
2. Зафиксируйте проверенный состав исходников и выполните автоматизированную подготовку из чистой копии этого коммита на Windows. Она запускает тесты, Android lint, сборки, проверку состава, подпись манифеста и верификацию с отдельным публичным ключом. Результат остаётся локальным. При имеющемся сертификате Authenticode уберите параметр `-AllowUnsignedWindows` и передайте сертификат electron-builder штатным способом.
```powershell
pwsh -File scripts/prepare-release-candidate.ps1 -PreviousVersion 0.14.0 -PreviousAndroidCode 85 -Gitleaks 'gitleaks.exe' -AllowUnsignedWindows -Offline
```

3. Сверьте кандидата и тесты обновления с предыдущей совместимой версией Windows и Android. Сверьте сохранение профиля и сертификат APK. Добавьте `docs/releases/<версия>.ru.md` перед сборкой. Проверьте статус исходников, Gitleaks и исключение локальных материалов перед любым переносом файлов в GitHub.
4. Получите подтверждение владельца на конкретные проверенные файлы. Создайте обычный черновик на согласованном теге и прикрепите Windows-установщик, подписанный APK, `wiley-update-v2.json`, `SHA256SUMS.txt` и список изменений. После проверки черновика владелец публикует его как Latest. История выпусков сохраняется.

GitHub Actions проверяет исходники и отдельно может подготовить Windows-артефакт с правом чтения. Защищённая подпись пока выполняется на машине владельца. Публичный процесс WilDia использован как образец последовательности «тесты → подпись APK → apksigner и versionCode → SHA‑256 → релизные активы». В WileyAI подпись распространяется и на манифест, а публикация отделена от сборки. [Workflow WilDia](https://github.com/WildLIK/WilDia/blob/main/.github/workflows/ci-and-release.yml) · [Манифест WilDia](https://github.com/WildLIK/WilDia/blob/main/tools/build_release_manifest.py).

## Ключи WileyAI

Android PKCS#12 хранится в `D:\secrets\wileyai-release.keystore`. Рядом создан отдельный каталог `wileyai-release.vault` с зашифрованным PKCS#8 для подписи манифеста P‑256, открытыми отпечатками и DPAPI-зашифрованными паролями текущего пользователя Windows. Файлы за пределами Git. Программа подписи получает пароль только в окружении локального дочернего процесса. Для Windows-сборки передаётся только открытый ключ.

```powershell
.venv/Scripts/python.exe scripts/release-vault.py fingerprints
.venv/Scripts/python.exe scripts/release-vault.py backup 'X:\WileyAI-release.wileybackup'
```

Перед публикацией владелец сохраняет зашифрованную резервную копию ключей на отдельном носителе и отдельно хранит пароль восстановления. Копия привязана к этому паролю, тогда как основной DPAPI-блок привязан к учётной записи Windows. Публикуются только открытые данные из [release-trust.json](release-trust.json). Безопасная проверка Windows использует подписанный манифест и SHA‑256. Authenticode отличает издателя в самой ОС и для этого выпуска не используется.

Для восстановления на новой машине вызовите `.venv/Scripts/python.exe scripts/release-vault.py --keystore 'D:\secrets\wileyai-release.keystore' restore 'X:\WileyAI-release.wileybackup'`. Команда принимает только свободные пути, сверяет оба открытых отпечатка и привязывает пароль к DPAPI текущего профиля. Существующие ключи сохраняются.

## Первая установка и восстановление

Локальные debug APK, включая 0.14.44 с versionCode 86, подписаны **WileyAI Local Debug**. Установить APK с новым release-ключом поверх такого пакета без отдельной миграции Android не позволит. Перед первым распространением определить, у каких инсталляций уже постоянный сертификат. Отдельно согласовать перенос с debug, включая инвентаризацию и сохранение данных.

Сборки, выпущенные раньше доверенного ключа, получают первое обновление вручную из проверенного источника. На Windows это первый NSIS с ключом проверки в ресурсах и контрольной суммой в подписанном манифесте. На Android такой переход применим к установленному APK с совпадающим сертификатом. Перед подписанием проверьте лицензии и происхождение встроенных моделей.

При проблеме обновления публикуется исправленная версия с более высоким SemVer/versionCode и тем же сертификатом. При повторной установке Windows пригоден проверенный подписанный установщик. До публикации проверить оба перехода со старой совместимой сборки и повтор после отмены.
